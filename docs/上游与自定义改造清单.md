这份清单把当前仓库分为两层，便于后续维护、升级和归因：

- **上游基线**：`a793534`，上游 `v0.3.5`，日期为 2025-05-17。
- **本仓库自定义层**：从 `d0de947`（2026-06-22）开始，由 `dahaibuhai` 在该 fork 中提交的改动。

“上游已有”不等同于某一位作者独自完成，而是指在上述上游基线中已经存在的能力；“本仓库新增/修改”则由本仓库的提交历史确认。

## 3. 当前代码的来源边界

### 上游核心，继续沿用

- `main.py` 的 Zotero 语料获取、arXiv RSS/详情检索、embedding 重排和邮件主流程。
- `recommender.py` 的相似度排序。
- `llm.py` 的本地 LLM / API TLDR 接口。
- `paper.py` 的 arXiv 论文对象、PDF/源码信息和机构提取。
- `construct_email.py` 的邮件框架、SMTP 发送、星级展示。
- Docker、GitHub Actions、基础 Secrets/Variables 和 `ZOTERO_IGNORE` 机制。

### 本仓库自定义层

- `keyword_ranker.py`：关键词规则和分数计算。
- `providers/common.py`：供外部来源使用的通用论文对象。
- `providers/semantic_scholar.py`：Semantic Scholar 检索与容错。
- `providers/crossref.py`：Crossref 期刊目录检索。
- `dedupe.py`：跨来源统一去重。
- `sent_history.py`：已发送论文记录与期限过滤。
- `.github/workflows/main.yml`、`.github/workflows/test.yml` 中的多源环境变量、历史保存和新的运行时配置。
- `main.py`、`construct_email.py`、`paper.py` 中为上述能力接入的改动。

## 4. 后续维护规则

1. 上游升级时，先比较上游对“上游核心”文件的改动，再重新确认自定义导入和调用点仍存在。
2. 不要删除 `providers/`、`dedupe.py`、`sent_history.py` 或 `keyword_ranker.py`，除非同时移除 `main.py` 和两个 workflow 中的对应调用。
3. 修改研究主题只改配置词表和查询，不应改动跨来源去重、历史去重或容错逻辑。
4. 若要新增来源，先实现为独立 provider，再接入统一去重和历史过滤；不要在邮件模板里为单一来源写死字段。

这份边界表可作为以后同步上游、排查回归和继续扩展来源时的核对清单。
